One Server, Many Clients

One copy of the code · one process per client · each client has its own database, domain and login settings

How it works: the code is installed once in /var/www/torcap. For each client you start one more PM2 process from that same code, with its own database address, secret, port and domain. A git pull and one build update every client together.

Login differences per client need no code change. WhatsApp sign-in on or off, the WhatsApp provider credentials, and branch currency are all read from each client's own company table. Only the template name comes from the process settings below. 1. A database and user for each client

Repeat for each client (change the names and password):

sudo -u postgres psql
CREATE USER torcap_client2 WITH PASSWORD 'AnotherStrongPassword456';
GRANT CONNECT ON DATABASE client2_db TO torcap_client2;
\c client2_db
GRANT USAGE ON SCHEMA public TO torcap_client2;
GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA public TO torcap_client2;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO torcap_client2;
\q

2. One settings file for all clients

This file holds passwords, so keep it outside the code folder (it must never go to GitHub):

sudo mkdir -p /etc/torcap
sudo nano /etc/torcap/ecosystem.config.js
const cwd = "/var/www/torcap";
module.exports = {
  apps: [
    {
      name: "torcap-sona",
      cwd,
      script: "npm",
      args: "start -- -p 3000",
      env: {
        NODE_ENV: "production",
        DATABASE_URL: "postgresql://torcap:Password1@localhost:5432/sit_sonasa2?schema=public",
        SESSION_SECRET: "64-CHARACTER-RANDOM-VALUE-FOR-SONA",
        WHATSAPP_OTP_TEMPLATE_NAME: "otp"
      }
    },
    {
      name: "torcap-client2",
      cwd,
      script: "npm",
      args: "start -- -p 3001",
      env: {
        NODE_ENV: "production",
        DATABASE_URL: "postgresql://torcap_client2:AnotherStrongPassword456@localhost:5432/client2_db?schema=public",
        SESSION_SECRET: "A-DIFFERENT-64-CHARACTER-RANDOM-VALUE",
        WHATSAPP_OTP_TEMPLATE_NAME: "otp"
      }
    }
  ]
};
sudo chmod 600 /etc/torcap/ecosystem.config.js
openssl rand -hex 32     # run once per client for each SESSION_SECRET

Settings given here take priority over any .env file in the folder, so you can leave the folder's .env out entirely (the build in step 3 does not need a database address).

3. Build once, start all

cd /var/www/torcap
npm ci
npx prisma generate
npm run build
pm2 delete all 2>/dev/null
pm2 start /etc/torcap/ecosystem.config.js
pm2 save
pm2 status      # every client should show: online

4. One domain per client in Nginx

Create one site file per client, for example /etc/nginx/sites-available/torcap-client2. It is the same as the first one but with a different domain and port, and the rate-limit line limit_req_zone must appear only once in total (keep it in the first file):

server {
    listen 80;
    server_name client2.yourcompany.com;

    location /api/auth/ {
        limit_req zone=authlimit burst=5 nodelay;
        limit_req_status 429;
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
sudo ln -s /etc/nginx/sites-available/torcap-client2 /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d client2.yourcompany.com

Point each client's domain (DNS A record) at the server before running certbot.

5. Update every client at once

cd /var/www/torcap
git pull
npm ci
npx prisma generate
rm -rf .next
npm run build
pm2 restart all --update-env

6. Adding a new client later

  1. Create its database and database user (step 1).
  2. Add one more block in /etc/torcap/ecosystem.config.js with the next port and a new secret.
  3. pm2 start /etc/torcap/ecosystem.config.js --only torcap-newclient then pm2 save.
  4. Add the Nginx site file, reload, run certbot.
Each client's database must contain the TORCAP tables the portal reads, plus the company table with the WhatsApp settings. Never run npx prisma db pull against any of them. If a client's database differs from the Sona one (different column names), tell me before deploying: the single shared schema.prisma must match all of them.
Different servers instead? If a client wants its own separate server, nothing changes in the code: follow GITHUB-GUIDE.html and DEPLOYMENT-GUIDE.html on that server with that client's database.
