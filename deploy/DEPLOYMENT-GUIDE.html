TORCAP Scheme Portal – Production Deployment

Linux server (Ubuntu 22.04 / 24.04) · PostgreSQL on the same server · Nginx + HTTPS + PM2

Before you start, have ready: a server with root/sudo access, a domain name (e.g. portal.yourcompany.com) pointed at the server's IP address (an "A record" in your DNS), and the project zip torcap-scheme-portal.zip. Replace every portal.yourcompany.com below with your real domain. Commands starting with sudo need admin rights.
Golden rule: never run npx prisma db pull. It rewrites the curated prisma/schema.prisma from the whole ERP database and breaks the build. Only npx prisma generate is ever needed.

1Prepare the server

sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git unzip ufw nginx postgresql postgresql-contrib
# Node.js 20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # should print v20.x
sudo npm install -g pm2

2Database

If the portal uses the existing ERP database on this same server, skip creating a new one and just create a dedicated user for the portal. Open the Postgres prompt:

sudo -u postgres psql

Then type (change the password; use letters and numbers, avoid symbols like @ : / to keep the URL simple):

CREATE USER torcap WITH PASSWORD 'ChangeThisStrongPassword123';
GRANT CONNECT ON DATABASE sit_sonasa2 TO torcap;
\c sit_sonasa2
GRANT USAGE ON SCHEMA public TO torcap;
GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA public TO torcap;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO torcap;
\q

If you need to move your current database to this server, on the old machine run pg_dump -Fc -U postgres sit_sonasa2 > sit_sonasa2.dump, copy the file over, then on the server: sudo -u postgres createdb sit_sonasa2 and sudo -u postgres pg_restore -d sit_sonasa2 sit_sonasa2.dump.

Postgres on the server listens only on the server itself by default, which is what you want. Do not open port 5432 to the internet.

3Upload and unpack the portal

sudo mkdir -p /var/www/torcap
sudo chown $USER:$USER /var/www/torcap
# upload torcap-scheme-portal.zip to the server first (WinSCP / FileZilla / scp), e.g. into /tmp
unzip /tmp/torcap-scheme-portal.zip -d /var/www/torcap
cd /var/www/torcap
ls    # you should see package.json, prisma, src ...

If the zip creates an extra sub-folder, cd into it so that package.json is in your current folder.

4Configure the environment file

Generate a secret and create .env:

openssl rand -hex 32          # copy the output
nano .env

Paste the following, filling in your values (save with Ctrl+O, Enter, Ctrl+X):

DATABASE_URL="postgresql://torcap:ChangeThisStrongPassword123@localhost:5432/sit_sonasa2?schema=public"
SESSION_SECRET="PASTE_THE_64_CHARACTER_OUTPUT_HERE"
WHATSAPP_OTP_TEMPLATE_NAME="otp"
NODE_ENV="production"

Lock the file down:

chmod 600 .env
  • Port 5432 is the Linux default (your Windows test used 5433). Check with sudo -u postgres psql -c "show port;".
  • SESSION_SECRET must be 32+ characters. The site will refuse logins without it. Changing it later logs every customer out.
  • WhatsApp credentials are read from the company table, not from this file.
  • Set WHATSAPP_OTP_TEMPLATE_NAME to the exact approved template name in saudialert.

5Build and test

npm ci
npx prisma generate
npm run build
npm start -- -p 3000     # quick test; stop with Ctrl+C

In a second terminal: curl -I http://localhost:3000/login should show 200.

6Run it permanently with PM2

cd /var/www/torcap
pm2 start npm --name torcap-portal -- start -- -p 3000
pm2 save
pm2 startup        # copy and run the single command it prints
pm2 status

Useful: pm2 logs torcap-portal (live logs), pm2 restart torcap-portal.

7Nginx reverse proxy with login rate limiting

This also protects the WhatsApp login from being spammed (each request costs a message).

sudo nano /etc/nginx/sites-available/torcap
limit_req_zone $binary_remote_addr zone=authlimit:10m rate=5r/m;

server {
    listen 80;
    server_name portal.yourcompany.com;

    client_max_body_size 2m;

    location /api/auth/ {
        limit_req zone=authlimit burst=5 nodelay;
        limit_req_status 429;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
sudo ln -s /etc/nginx/sites-available/torcap /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

8HTTPS (required)

Session cookies are marked secure in production, so login only works over HTTPS.

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d portal.yourcompany.com
# choose "redirect HTTP to HTTPS" when asked. Renewal is automatic.

9Firewall

sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo ufw status

Port 3000 and 5432 stay closed to the outside; only Nginx talks to the portal.

11Backups

sudo mkdir -p /var/backups/torcap
sudo crontab -e

Add this line (daily at 2 AM, keeps 14 days):

0 2 * * * sudo -u postgres pg_dump -Fc sit_sonasa2 > /var/backups/torcap/db_$(date +\%F).dump && find /var/backups/torcap -name "*.dump" -mtime +14 -delete

Also copy these backups off the server regularly.

12Updating to a new version

cd /var/www
cp -r torcap torcap_backup_$(date +%F)       # rollback copy
# upload the new zip, then unzip OVER the folder but keep .env:
unzip -o /tmp/torcap-scheme-portal.zip -d /var/www/torcap
cd /var/www/torcap
npm ci
npx prisma generate
rm -rf .next
npm run build
pm2 restart torcap-portal

Rollback: pm2 stop torcap-portal, rename the current folder, rename torcap_backup_DATE back to torcap, then pm2 start again from it.

Security notes

  • Sessions now use a signed cookie (tamper-proof, 8-hour expiry) and the login form is rate limited by Nginx.
  • The saudialert API address stored in the company table starts with http://, so its username and password travel unencrypted from your server. Ask the provider whether an https:// address is available and update that column if so.
  • The portal's database user has only read/insert/update rights, no delete or schema changes.
  • Keep the OS updated: sudo apt update && sudo apt upgrade monthly.
