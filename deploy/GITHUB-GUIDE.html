Step 1: Put the Portal on GitHub, Step 2: Deploy to the Server

Flow: your PC → GitHub (private repository) → Linux server pulls from GitHub

Make the repository Private. The code contains your business logic and database structure. The .env file (passwords) is already excluded by .gitignore and must never be uploaded.

A. One-time setup on your Windows PC

  1. Install Git: download from git-scm.com/download/win, install with all default options.
  2. Create a free account at github.com if you do not have one.
  3. On GitHub click + → New repository. Name: torcap-scheme-portal. Choose Private. Do not tick "Add a README". Click Create repository. Keep that page open: it shows your repository address, like https://github.com/YOURNAME/torcap-scheme-portal.git.

B. Upload the project (Command Prompt)

Open Command Prompt inside your project folder (the one containing package.json) and run these one at a time:

git config --global user.name "Your Name"
git config --global user.email "sajeevn2000@gmail.com"
git init
git add .
git status

Check the list: .env, node_modules and .next must not appear. Then:

git commit -m "TORCAP scheme portal first version"
git branch -M main
git remote add origin https://github.com/YOURNAME/torcap-scheme-portal.git
git push -u origin main

A browser window opens asking you to sign in to GitHub; approve it. Refresh the GitHub page and your files appear.

C. Connect the server to GitHub (one time, on the server)

A private repository needs the server to prove who it is. The safest way is a read-only "deploy key".

ssh-keygen -t ed25519 -C "torcap-server" -f ~/.ssh/torcap_deploy -N ""
cat ~/.ssh/torcap_deploy.pub

Copy the single line it prints. On GitHub open the repository → Settings → Deploy keys → Add deploy key, title torcap-server, paste the line, leave "Allow write access" unticked, Save. Back on the server:

cat >> ~/.ssh/config <<'EOF'
Host github.com
  IdentityFile ~/.ssh/torcap_deploy
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config
ssh -T git@github.com

Type yes if asked. You should see "Hi ... You've successfully authenticated".

D. First deployment on the server

This replaces Step 3 (upload zip) of the Deployment Guide. Do Steps 1 and 2 (server tools and database) from that guide first.

sudo mkdir -p /var/www/torcap
sudo chown $USER:$USER /var/www/torcap
git clone git@github.com:YOURNAME/torcap-scheme-portal.git /var/www/torcap
cd /var/www/torcap

Then continue with Deployment Guide Step 4 (create .env), Step 5 (build), and onwards. The .env is created only on the server.

E. Every future update

On your PC after any change:

git add .
git commit -m "Describe what you changed"
git push

On the server:

cd /var/www/torcap
git pull
npm ci
npx prisma generate
rm -rf .next
npm run build
pm2 restart torcap-portal

Rollback if a new version has a problem:

cd /var/www/torcap
git log --oneline -5          # find the previous version's code (first 7 letters)
git checkout PREVIOUSCODE
npm ci && npx prisma generate && rm -rf .next && npm run build
pm2 restart torcap-portal
# to return to latest later:  git checkout main && git pull
Reminders: never run npx prisma db pull; never commit .env; the file Sona_Guideline.pdf in the project is uploaded too, so remove it first (git rm --cached Sona_Guideline.pdf before the first commit, or delete it) if you do not want it on GitHub.
